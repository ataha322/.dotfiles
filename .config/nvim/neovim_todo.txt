8. Need a better ui prompt. right now we use vim.ui.input() which can be used in plain neovim or overridden by plugins. however, I want a different behaviour:
    * Since the inline-edit feature should only be triggered from visual selection, then I want the prompt to appear right above or below the selected lines, making visible space for input once action is hit, starting from 1-line.
    * How to decide above or below:
        - If user started selecting at the top and went down, then his current cursor is at the botton. input prompt should appear below.
        - If user started selecting at the bottom and went up, then his current cursor is at the top. input prompt should appear above.
    * The prompt should be closable how you would normally close a floating window. if closed while processing, request should be cancelled.
    * Prompt should be submitted with <enter> in normal mode (but only when cursor is in our prompt.
    * Color of prompt should be different from the rest of the buffer. pick something standard. if we're doing it via a floating window, then NormalFloat is a good candidate (maybe it's even default?)
    * This is what I got recommended:
        > Recommended approach: a 1-line float anchored to the text, plus a virtual line to reserve the space.
        > 
        > A float with relative="win" and bufpos follows the buffer position as you scroll, and height=1 gives you your one-line prompt.
        > A float alone covers the code above or below the selection. To avoid that, add an extmark with a blank virt_lines entry (virt_lines_above=true). That pushes the text down and leaves a hole for the float to sit in.
